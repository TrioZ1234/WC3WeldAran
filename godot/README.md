# godot — нативная сборка

Проект Godot 4.3+, собирающий тот же мир из тех же данных, что и веб-клиент.
Нужен для нативных сборок под Windows, Linux и macOS.

## Запуск

```bash
python3 build.py путь/к/WFWA.w3x   # из корня репозитория
```
Затем открыть каталог `godot/` в Godot 4.3+ и запустить сцену.

`build.py` создаёт `godot/data` и `godot/assets` — ссылки на `build/`.
На Windows без Developer Mode симлинки недоступны, скрипт молча копирует.

## Что реализовано

- `scripts/map_data.gd` — загрузка `terrain.bin` и JSON. Раскладка бинарника
  читается из `terrain.json`, а не зашита в код: изменение конвейера даст
  ошибку загрузки, а не тихую порчу данных.
- `scripts/world.gd` — ландшафт чанками 32 × 32 тайла (225 чанков, чтобы
  работал frustum culling) и размещённые объекты через `MultiMesh`.

25 222 декорации отдельными нодами обошлись бы дороже в накладных расходах
дерева сцены, чем в самой отрисовке, поэтому используется `MultiMesh`.

## Системы координат

В данных карты — координаты Warcraft III: X на восток, Y на север, Z вверх.
Godot использует Y вверх, поэтому `MapData.to_godot()` переводит
`(x, y, z)` → `(x, z, -y)`. Все преобразования собраны в одном методе.

## Границы ответственности

Проект **не** разбирает `.w3x` и ничего не выводит из карты сам — он
потребляет готовый результат конвейера. Единственный источник контента —
`tools/`. Так веб-клиент и нативная сборка не могут разойтись по содержимому.

Подробнее о разделении между двумя клиентами: [../docs/04-frontends.md](../docs/04-frontends.md).
