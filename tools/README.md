# tools — конвейер извлечения и конвертации

Python 3.8+, **без внешних зависимостей**. Всё, что нужно для чтения форматов
Warcraft III, реализовано здесь.

## Библиотека форматов — `wc3/`

| Модуль | Назначение |
|---|---|
| `mpq.py` | Архивы MPQ: заголовок, хеш- и блок-таблицы, дешифрование, секторное чтение, кодеки zlib / bzip2 / sparse / PKWARE |
| `explode.py` | Распаковка PKWARE DCL — порт `blast.c`. В стандартной библиотеке Python отсутствует, без него архив не читается |
| `w3x.py` | Парсеры файлов карты: `w3i`, `w3e`, `doo`, объектные данные, `wts`, `imp` |
| `slk.py` | Таблицы SYLK — стоковый баланс Warcraft III (`UnitData.slk` и семейство) |

Аудиокодеки MPQ (Huffman, ADPCM) не реализованы — в этой карте не встречаются.
При появлении `MPQError` о неподдерживаемом кодеке смотреть `mpq.decompress()`.

## Скрипты

### `extract_map.py`
```bash
python3 tools/extract_map.py <карта.w3x> <каталог>
```
Распаковывает архив целиком. Имена берутся из внутреннего `(listfile)`,
плюс проверяется список стандартных файлов карты — на случай защищённых архивов.
Пишет `_manifest.json` с перечнем файлов и ошибок. Сбой одного файла не
прерывает распаковку.

### `analyze_map.py`
```bash
python3 tools/analyze_map.py <каталог> [--json отчёт.json]
```
Отчёт по содержимому: паспорт карты, ландшафт, размещённые объекты,
пользовательские объекты, скрипт, вес ассетов.

### `analyze_jass.py`
```bash
python3 tools/analyze_jass.py <war3map.j> [--json api.json]
```
Определяет поверхность API движка: функции, которые скрипт вызывает, но не
определяет, — то есть то, что обязан предоставить рантайм. Группирует по
подсистемам и сортирует по частоте. Этот список — контракт на реализацию.

### `export_data.py`
```bash
python3 tools/export_data.py <каталог> <каталог-данных>
```
Конвертирует игровые таблицы в JSON с уже подставленными локализованными
строками:

| Файл | Содержимое |
|---|---|
| `map.json` | Паспорт, игроки, фракции, заголовок ландшафта |
| `terrain.json` | Высоты, вода, текстуры по точкам |
| `doodads.json` | Размещённые декорации |
| `units.json` | Размещённые юниты и предметы |
| `objects/*.json` | Пользовательские объекты по категориям |
| `strings.json` | Таблица строк |

## Заметки по форматам

Мелочи, на которых легко споткнуться:

- **`.w3x` — это не сразу MPQ.** Сначала 512 байт заголовка `HM3W`.
  `MPQArchive.open_map()` это учитывает.
- **Блок случайного юнита в `war3mapUnits.doo` переменной длины.** Размер
  зависит от ведущего флага (4 / 8 / 4 + n×8 байт). Фиксированное чтение
  рассинхронизирует парсер к концу файла.
- **Уровни есть не у всех объектных данных.** Поля `level` / `dataPointer`
  присутствуют только в `w3a`, `w3d`, `w3q`.
- **Кодировка строк.** UTF-8, с откатом на cp1251 — старые редакторы писали
  в кодировке системы.
- **`hero_level` по умолчанию равен 1** у обычных юнитов. Признаком героя
  считать `> 1`.

### `fetch_war3_data.py`
```bash
python3 tools/fetch_war3_data.py [каталог]
```
Забирает **только данные** Warcraft III — скрипты и таблицы, около 4 МБ:
`common.j`, `Blizzard.j`, `*.slk` и `*MetaData.slk`. Графика и звук не
скачиваются: это большая и юридически чувствительная часть, а логике движка
она не нужна.

Результат кладётся в `build/war3/`, который git игнорирует. Ничего от Blizzard
в репозиторий не попадает — каждый разработчик получает свою копию, так же как
извлёк бы её из установленной игры.

### `export_stock.py`
```bash
python3 tools/export_stock.py <каталог-war3> <каталог-данных> [--json отчёт.json]
```
Разрешает объекты карты против стоковых прототипов. Карта хранит объекты как
разницу («возьми `hbla`, поменяй 20 полей»), поэтому без стоковых таблиц у
кастомного юнита неизвестно даже число хитов.

Коды полей (`uhpm`) сопоставляются с колонками таблиц через `*MetaData.slk` —
вручную ничего не прописано. На выходе `build/data/stock/*.json` (прототипы) и
`build/data/resolved/*.json` (объекты карты со всеми полями).

Текущий результат: 1 320 из 1 320 объектов разрешены, 88 642 поля восстановлено.

### `analyze_assets.py`
```bash
python3 tools/analyze_assets.py <каталог-распаковки> <каталог-данных> [--json отчёт.json]
```
Считает, сколько ещё нужно от установленного Warcraft III: модели, текстуры,
иконки, звуки, стоковые прототипы. Превращает вопрос «что мешает
самостоятельной сборке» в отслеживаемое число.

### `fetch_war3_art.py`
```bash
python3 tools/fetch_war3_art.py [--out каталог] [--json отчёт.json]
```
Скачивает ровно ту графику, которую перечислил `analyze_assets.py`, — из
десяти тысяч файлов зеркала берутся только нужные несколько сотен.

Каждая ссылка разрешается в одно из трёх мест, и различать их важно: зеркало
Warcraft III, сама карта, либо никуда. Последнее — мёртвые ссылки в объектных
данных, и их полезно видеть отдельно.

Результат: 919 из 922 ссылок, 39.4 МБ в `build/war3/art/` (git игнорирует).
