# 05 — Что нужно, чтобы игра запускалась без Warcraft III

Документ отвечает на один вопрос: что отделяет текущее состояние от
самостоятельной игры, которой не нужен установленный Warcraft III.

Все числа получены из карты и пересобираются командами в конце документа.

## Барьер 1 — контракт нативных функций

Ключевое решение: **`common.j` и `Blizzard.j` загружаются в VM как обычные
скрипты**, а не переписываются руками.

- `common.j` — 1 160 деклараций нативных функций, 91 тип хендла, 426 констант.
  Заглушки получают объявленный тип возврата вместо угаданного, а константы —
  настоящие значения. Неизвестных констант было 36, стало **0**.
- `Blizzard.j` — 923 готовые функции. Все обёртки `*BJ` исчезли из контракта:
  они теперь исполняются, а не имитируются, и поведение совпадает с оригиналом
  по построению.

```
загружено 1 941 функция (923 Blizzard.j + 1 018 карта)
исполнено 13 140 вызовов нативных функций
  ├─ 10 628 обеспечены настоящим поведением   80.9 %
  └─  2 512 заглушены — 65 функций
```

Осталось **65 подлинных нативных функций**. Не 321: та цифра включала обёртки,
которых больше нет в контракте. Крупнейшие узлы: регистрация событий
(`TriggerRegisterPlayerUnitEvent` — 1 309 вызовов), телепорты (288),
альянсы (110), предметы (79), звук (153).

## Барьер 2 — системы рантайма

Половина закрыта: **время идёт**. После `main()` запускаются часы на 32 Гц,
таймеры срабатывают, триггеры вычисляются, а карта сама порождает юниты —
2 310 после инициализации, 2 394 к первой минуте.

| Система | Состояние |
|---|---|
| Часы с фиксированным шагом 1/32 с | ✅ 392x реального времени |
| Планировщик таймеров | ✅ одноразовые, периодические, пауза |
| Корутины для `TriggerSleepAction` | ✅ потоки на генераторах |
| Реестр событий триггеров | ✅ 1 452 привязки, порядок сохранён |
| Бой, поиск пути, приказы | Нет |
| Связь с рендером | Нет — в клиентах кубы-заглушки |
| Интерфейс, звук, ИИ, сеть | Нет |

Корутины оказались обязательными, а не желательными: `PolledWait` в
`Blizzard.j` — цикл, который двигается только за счёт сна внутри себя, и
синхронный обходчик там крутится вечно.

Осталось главное содержательное: бой, приказы и поиск пути. Теперь их есть
на чём считать — характеристики всех объектов известны (барьер 3a).

## Барьер 3a — данные. Закрыто

### В чём была проблема

Карта хранит объекты как **разницу** с Warcraft III: «возьми прототип `hbla`,
поменяй эти 20 полей». Всё остальное наследуется от стокового объекта, которого
в `.w3x` нет. Без War3.mpq у кастомного юнита неизвестно даже число хитов.

### Как решено

`tools/export_stock.py` читает стоковые таблицы SLK, сопоставляет коды полей
(`uhpm`) с колонками таблиц через `*MetaData.slk`, и накладывает модификации
карты сверху. На выходе — полные самодостаточные определения.

```
1 320 объектов карты
 └─ 1 320 разрешены полностью        100 %
     └─ 88 642 поля восстановлено из стоковых прототипов
```

| Категория | Объектов | Полей унаследовано |
|---|---:|---:|
| Юниты | 473 | 70 799 |
| Дудады | 226 | 6 554 |
| Разрушаемые | 101 | 4 942 |
| Способности | 352 | 2 816 |
| Предметы | 84 | 2 449 |
| Улучшения | 65 | 1 044 |
| Баффы | 19 | 38 |

Нерешённых прототипов — **ноль**.

### На примере

Юнит `h000` («Grot»), построен поверх прототипа `hbla`:

| Поле | Задано картой | После разрешения |
|---|---|---|
| Имя | Grot | Grot |
| Здоровье | 20000 | 20000 |
| Тип атаки | — неизвестно — | fort |
| Броня | — неизвестно — | 5 |
| Радиус обзора | — неизвестно — | 900 |
| Модель | — неизвестно — | buildings\human\Blacksmith\Blacksmith |
| Время постройки | — неизвестно — | 70 |

Карта задаёт 19 полей, из War3.mpq приходило 130. Теперь известны все 136.

**Следствие:** игровая логика — бой, экономика, технологии, баланс — работает
без установленного Warcraft III. Осталась зависимость только по картинке.

## Барьер 3b — ассеты. Получены

`tools/fetch_war3_art.py` берёт ровно то, что перечислено в отчёте
`asset-gap.json`, — ничего лишнего из десяти тысяч файлов зеркала.

```
922 ссылки на графику
 ├─ 763 из зеркала Warcraft III   скачано, 39.4 МБ
 ├─ 156 везёт сама карта          уже распакованы
 └─   3 не разрешаются нигде      мёртвые ссылки в объектных данных
```

**919 из 922 — 99.7 %.** Скачано 163 модели MDX и 546 текстур BLP; выборочная
проверка нашими же парсерами `mdx.py` и `blp.py` — 60/60 и 60/60 без ошибок.

Мёртвых ссылки три: `TeamColor20.blp`, `btnspellgilles3.blp`,
`war3mapimported\palm_portrait.mdl`. Это остатки в объектных данных самой карты,
а не пробел движка.

Технически барьер снят: движку есть что рисовать. Остаётся **вопрос
распространения**, а не доступности:

**А. Извлекать из установленного Warcraft III на машине игрока.**
Конвейер уже читает MPQ, нужен лишь установщик, который найдёт War3.mpq.
Юридически чисто, игрок пользуется тем, чем владеет. Но это не «без варкрафта».

**Б. Заменить своими.** Единственная настоящая независимость. Работа
художника, сопоставимая по срокам со всем движком.

**В. Гибрид.** Запускаться в режиме А, подставлять свои ассеты по мере
готовности, начиная с самых частых юнитов. Требует, чтобы движок с самого
начала брал ассет из любого источника — **это решение принимается сейчас**.

Теперь, когда данные отвязаны, путь Б стал постепенным: можно менять модель
одного юнита, не трогая его характеристики.

## Правовая заметка

`common.j`, `Blizzard.j` и таблицы SLK **не хранятся в этом репозитории**.
`tools/fetch_war3_data.py` кладёт их в `build/war3/`, который игнорируется git.
Каждый разработчик получает свою копию — так же, как извлёк бы её из
установленной игры. Зеркало `WarRaft/War3.mpq` используется как удобный
источник; содержимое остаётся собственностью Blizzard, и вопрос распространения
в составе готовой сборки решается отдельно, см. барьер 3b.
