**Проверка пройдена.** `config()` и `main()` доходят до конца:

```
ok  globals        0 шагов
ok  config       259 шагов
ok  main      38 863 шагов, 26 мс
```

Состояние мира строится реально: 2 310 юнитов, 12 игроков, 12 команд,
12 стартовых точек, 1 360 записей технологий, 3 194 хендла.

Парсер на TypeScript и `analyze_jass.py` на Python сошлись полностью:
1 018 функций, 811 глобалов, расхождений — ноль.

**Главное решение этапа.** `common.j` и `Blizzard.j` загружаются в VM как
обычные скрипты. Это убирает все 46 обёрток `*BJ` из контракта — они
исполняются, а не имитируются, — а декларации из `common.j` дают заглушкам
объявленный тип возврата. Неизвестных констант было 36, стало **0**.

Всего загружается 1 941 функция; из 13 140 исполненных вызовов 80.9 %
обеспечены настоящим поведением. Осталось **65 подлинных нативных функций**.

Отчёт: [`data/jass-runtime.json`](data/jass-runtime.json).

## Этап 3.7 — Время идёт ✅ Готово

- [x] Часы с фиксированным шагом 1/32 с — та же частота, что у Warcraft III
- [x] Очередь таймеров: одноразовые, периодические, пауза и возобновление

- [x] `TriggerEvaluate` реально исполняет условия
- [x] Бюджет инструкций на поток, а не на весь мир

**Проверка пройдена.** После `main()` запускаются часы, и карта живёт сама:

```
300 с игрового времени за 766 мс   =   392x реального времени
  тиков                 9 600 при 32 Гц
  срабатываний таймеров 66 760
  вычислений триггеров   9 959
  ошибок                     0
```

Главное доказательство — **карта сама порождает юниты**: 2 310 после `main()`,
2 394 к первой минуте. 84 юнита 14 типов по её собственной логике старта.

Корутины оказались не удобством, а необходимостью: `PolledWait` в `Blizzard.j`
двигается только за счёт сна внутри цикла. До них один зависший вызов сжигал
50 миллионов инструкций и валил прогон; после — 136 тысяч и ноль ошибок.

Запуск: `node engine/cli/run-game.ts --seconds 300`.

## Хранение исходной карты

`.w3x` весит 25.6 МБ. Класть его в историю git не стоит — репозиторий распухнет,
а бинарник всё равно не диффится.

| Вариант | Комментарий |
|---|---|
| **GitHub Releases** | Просто, бесплатно, версии видны. Рекомендую |
| **Git LFS** | Удобно для частых версий, но ест квоту |
| Внешнее хранилище | Ссылка в README |

Если версий карты будет много — Releases с тегом на каждую.

## Порядок работы с репозиторием

- `main` — рабочая ветка
- Изменения конвейера сопровождаются пересборкой `docs/data/*.json`
- `build/` в git не попадает: всё внутри порождается из карты
